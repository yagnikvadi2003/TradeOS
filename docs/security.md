# Security review (phase 4)

| Area                | Status | Notes                                                                                                                                                                                                                                                  |
| ------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Authentication      | ✔      | REST is public read-only market data. `/ws/market` requires an HS256 session token before any subscription (anonymous until the users module). Token secret ≥ 32 chars, required in production.                                                        |
| Authorization       | ✔      | Per-key: catalog instruments only, option contracts only for option-chain underlyings, within token scope; per-client cap. Operator endpoints need `X-Operator-Key`; the OAuth callback is bound to a single-use, 10-min `state`.                      |
| CORS                | ✔      | Explicit origin allow-list, `GET/HEAD/OPTIONS` only. Same list gates WebSocket upgrades (`Origin`).                                                                                                                                                    |
| Helmet              | ✔      | Defaults + CSP in production. Frontend CSP/headers set by Caddy (`infrastructure/docker/Caddyfile`).                                                                                                                                                   |
| Rate limiting       | ✔      | Global throttler (`RATE_LIMIT_*`), stricter on `/realtime/token` (10/min) and the OAuth callback (5/min); WebSocket token bucket per client (`WS_MESSAGES_PER_SECOND`) with fatal close. `TRUST_PROXY` controls whether `X-Forwarded-For` is honoured. |
| WebSocket           | ✔      | Origin check, global and per-IP connection caps, auth timeout, payload cap (`maxPayload`), Zod-validated messages, subscription cap, server heartbeat, bounded per-client queues, backpressure hold.                                                   |
| Input validation    | ✔      | Zod on every REST param/query, every WS frame, every provider payload (twice: adapter + domain boundary).                                                                                                                                              |
| Secret management   | ✔      | Env only; Upstox token AES-256-GCM at rest; never in logs, responses, Sentry or the browser bundle (verified by grep of `dist/`).                                                                                                                      |
| Logging             | ✔      | No headers/bodies serialized; `authorization`, `cookie`, `x-operator-key` redacted; `code`/`state`/`token` query values redacted.                                                                                                                      |
| Dependencies        | ✔      | `pnpm audit --audit-level=high` clean after overrides (`multer`, `deepmerge-ts`, `mysql2`). Remaining moderates are dev-only (vitest, @swc/cli).                                                                                                       |
| CSRF                | n/a    | No cookie-based auth yet; token is sent in a WS frame, not a cookie. Revisit when sessions become cookies (SameSite + CSRF token).                                                                                                                     |
| XSS                 | ✔      | No `dangerouslySetInnerHTML`; JSON-LD is serialized from static config; CSP forbids inline scripts.                                                                                                                                                    |
| SSRF                | ✔      | Outbound requests only to `UPSTOX_API_BASE_URL`, validated as HTTPS `*.upstox.com`; no user-supplied URLs are fetched.                                                                                                                                 |
| Injection           | ✔      | Prisma parameterized queries; no raw SQL; no shell execution.                                                                                                                                                                                          |
| Resource exhaustion | ✔      | Body limit 64 KB; WS payload 16 KB; bounded coalescing queues; bounded pending OAuth states; metrics histograms bounded; provider subscription cap; in-flight coalescing on snapshot/quote requests.                                                   |
| Subscription abuse  | ✔      | Per-client key cap, per-key authorization, unauthorized keys counted (`unauthorizedSubscriptions`), rate limit closes abusive sockets.                                                                                                                 |
